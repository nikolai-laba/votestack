# Election data

The scripts in `scripts/` download official data into `data/raw/` and generate files in `data/build/`. Both folders are gitignored: regenerate them with

```sh
npm run data:fetch   # boundaries and address points (~100 MB)
npm run data:build   # precinct overlay/audit, contests, the Clerk's precinct districts, paper ballot order (needs pdftotext: brew install poppler)
npm run lookup -- "834 Lake St, Oak Park, IL 60301"
npm run data:audit   # compare with the Clerk's sample ballots
npm run data:incumbents  # incumbent labels → content/incumbents/ (after profiles:subjects)
npm run contests:export  # public race list → content/contests/ (after data:build or data:incumbents; commit it)
npm run data:load    # load into Supabase (apply supabase/migrations first; needs .env)
```

Test with public addresses (offices, libraries). Never commit or share real voter addresses.

`content/contests/{election date}.json` is the one file built from this data that is committed: every race and judge up for retention, each once, with the official candidate lists in ballot order. The site builds its race pages from it, so the build needs no database. Each race keeps the web address it was first given, even when the file is rebuilt.

## Campaign finance data

`node scripts/profiles/money.ts` downloads the FEC and ISBE files above (about 1.1 GB, cached for a day; `--refresh` forces a new download) and writes `data/build/profiles/money.json`. The filings name individual donors with their home addresses. Federal law bars using FEC contributor details for soliciting or commercial purposes, and VoteStack never shows individuals at all: the import keeps only totals, committees and organizations. ISBE's site has a `robots.txt` that disallows all crawling, so the import only downloads the published bulk data files and never scrapes the search pages.

## City of Chicago data

The City of Chicago's terms are not an open license: the City may require use of its data to stop at any time, and apps using it must show this disclaimer wherever they can be accessed or downloaded:

> This site provides applications using data that has been modified for use from its original source, www.cityofchicago.org, the official website of the City of Chicago. The City of Chicago makes no claims as to the content, accuracy, timeliness, or completeness of any of the data provided at this site. The data provided at this site is subject to change at any time. It is understood that the data provided at this site is being used at one's own risk.

Fallback if the City's terms become a problem: rebuild precinct boundaries from Census blocks.
